# 重排后的相关性阈值过滤

混合召回仍负责提供候选；阈值根据实际重排器的相关性评分过滤，再最多返回 `top_k` 个片段。结果可以少于 `top_k`，不会把低分或未评分片段补回。RRF 分数不参与阈值判断。

## 配置

在后端 `.env` 或启动进程环境中设置，修改 `.env` 后重启后端使其重新加载：

```dotenv
# 外部 reranker 启用时使用；按所选模型的分数尺度校准，允许有限负数。
RERANK_MIN_SCORE=

# 未配置外部 reranker、使用本地 LLM 重排时使用；范围 [0,10]。
# 6 是与下述“直接支持至少一个所问事实”规则对应的试验起点，未经完整标定。
LLM_RERANK_MIN_SCORE=6
```

代码和 `.env.example` 的默认值均为空，保持原有行为。本工作区 `.env` 已设置 `LLM_RERANK_MIN_SCORE=6` 作为试验配置，重启后端加载；清空该值即可恢复关闭状态。只读取**当前实际评分器**对应的阈值：外部模型不使用 LLM 的阈值，LLM 也不使用外部阈值。`0` 会启用过滤；空字符串或仅空白关闭。无效数值、NaN、Inf，以及超出范围的 LLM 值会使本次评分失败，不静默绕过阈值。

LLM 阈值模式的评分要求：0–3 分为无关或只有主题、标题、背景；4–5 分无法直接支持所问事实；6–8 分明确支持至少一个所问事实或必要计算规则；9–10 分直接、完整支持所问内容。跨文档问题的一部分有效证据可以保留，不要求每个片段独立回答整题。这些模型分数不是校准后的概率，仍需检查误判。

## 过滤与失败行为

- 少于或等于 K 个候选也必须评分；只有零候选才免评分。有效分数按降序排列，等分保留原召回顺序，边界等于阈值时保留。
- 未评分、分数非法、模型没看到的候选均不回填；评分失败时也不退回未筛选的原始 Top-K。
- LLM 在输入预算内选取完整片段，不用压缩前缀的高分认证整段原文。超预算的整块会跳过，并记录为未评分。
- 所有候选完成评分且均低于阈值时，标记 `below_threshold`：初轮允许查询重写，终轮报告证据不足。
- 评分器失败、配置无效，或尚有未评分候选且没有合格结果时，标记 `rerank_failed`：证据状态为 `unknown`，工具不把原候选送给回答模型。它不证明知识库里没有答案。
- 有合格结果而部分候选未评分时，只返回合格片段；追踪中保留未评分数量，随后仍由整体证据检查判断是否支持原问题。
- 复杂扩展若一支评分失败，整轮采用保守的 `unknown`，不靠另一支的部分片段宣称证据充分。

阈值开启时跳过父块预取和 Auto-merging，保留被实际评分的原始片段。父块目前只继承子块的最高分，无法据此证明父块全文相关；重新加入父块需要另行对父块正文评分。关闭阈值后沿用原合并行为。

## 追踪与评测

`retrieval_records[].meta.relevance_filter` 以及顶层 `relevance_filters` 保留每轮策略：

- 当前分数字段、阈值、配置项和状态。
- 候选总数、有效评分数、保留数、低于阈值数、未评分数及因 Top-K 截断数。
- 每个候选的 ID、来源、原文 SHA256、有效分数及 `kept` / `below_threshold` / `unscored` / `top_k_limit` 决策。

这使后续可以检查分数分布和未评分覆盖率，而不依赖仅保存最终 Top-K 的旧缓存。开启过滤时 LLM 不再固定只考虑前 `3*K` 个候选；会在预算内尝试全部候选的完整文本，仍可能因预算而省略部分候选。

阈值效果应同时报告：实际保留片段精确率、相关证据保留率、返回数量、空结果率、评分失败率、端到端回答准确率及耗时。在验证集选择阈值，锁定后再用独立题集验证。

原先固定分母的 `Precision@K` 继续使用 K：从 10 块删除 8 个无关块、保留 2 个相关块，实际保留精确率为 2/2，但原 `Precision@10` 仍是 2/10。旧的 [简历补测](RESUME_EVIDENCE_ACCURACY.md) 来自改动前的真实回答，不因这次功能修改自动更新为更高的分数。

本轮测试与本地真实探针记录保存在 `data/relevance_filter_20261004/`；真实探针仅用于检查评分、过滤和状态传播，不构成阈值最优性或整体效果提升的证据。
