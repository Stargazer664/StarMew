# 文档上传与删除异常恢复

故障事件、告警和问答耗时的使用入口与统计口径见 [故障定位说明](DIAGNOSTICS.md)。

此实现面向单机、单后端进程的求职演示部署。上传失败会恢复旧文件、Milvus 向量、PostgreSQL 父块及 BM25 统计；删除失败会恢复删除前的索引与统计，删除始终保留本地原文件。依赖不可用导致恢复失败时，保留恢复日志并暂停索引读写。它是跨存储的补偿机制，不是分布式 ACID 事务。

## 上传与恢复流程

1. 浏览器生成稳定的 `upload_id`，服务器将接收进度保存到 SQLite。相同 ID 与文件名重复提交只返回原任务；要提交另一个版本需生成新 ID。
2. 文件保存到独立的 `.staging/<job_id>/`，完整接收后解析、计算稠密向量。此阶段失败不会修改旧版本。
3. 提交前持久保存旧向量（含稠密、稀疏向量）、父块、BM25 全量统计及原文件备份，再替换索引和文件。
4. 发生异常时，尝试恢复全部存储。恢复成功后任务失败但可重试；恢复失败则标为“需要恢复”，保留日志。向量插入关闭 SDK 自动重试，避免响应丢失后 auto_id 重复插入。
5. 服务启动先处理残留日志：已提交的事务补写任务成功状态；其余事务恢复旧版本。还未提交的排队、解析任务标为中断，等待用户明确重试，不自动重新入库。
6. 上传、恢复、删除和检索共用进程内锁。检索等待写入结束；存在未恢复日志时拒绝检索，不返回混合版本。Milvus 读取使用 Strong；父块直接以 PostgreSQL 已提交数据为准，避免旧 Redis 缓存污染。

## 管理员看到什么

| 情况 | 页面处理 | 下一步 |
| --- | --- | --- |
| 解析、向量计算或提交失败，已恢复旧版本 | 显示失败阶段，保留任务与完整暂存文件 | 点击“重试处理”，复用已收到文件 |
| 接收文件失败或暂存文件丢失 | 显示失败，不允许使用残缺文件重试 | 重新选择文件上传 |
| 上传响应丢失、网络断开、轮询超时 | 按 upload_id 查询；无法确认则暂停批次并标为状态待确认 | 点击状态核对或重新进入文档页 |
| 依赖故障导致恢复未完成 | 显示需要恢复；索引读取和后续修改受阻 | 恢复 PostgreSQL、Milvus 或磁盘后，点击“恢复数据”，再重试处理 |
| 服务重启 | 任务记录保留，页面重新加载任务列表 | 对中断且可重试的任务明确重试 |

上传和恢复的 POST 遇网络错误、5xx 或响应解析失败时不会自动重放。前后端分离部署时优先使用配置或推断的后端地址。轮询达到十分钟仅代表客户端停止等待，不能据此判定服务器任务失败。

## 删除补偿与确认

删除也先持久保存 Milvus 向量、父块和 BM25 快照，再依次扣减统计、删除向量与父块。任一步失败执行补偿；进程中断后根据日志恢复。日志以 `operation=upload/delete` 区分操作，启动或手动恢复时更新对应任务库；旧上传日志没有 operation 字段时仍兼容处理。

删除不会移除本地原文件，补偿也不覆盖该文件。同步和异步删除复用相同流程。已经写入 committed 标记的删除只补写完成状态，不能因为任务库短暂故障就重新删除或恢复索引。

浏览器每次经确认的删除生成稳定 `delete_id`。响应丢失时按此 ID 核对，不重发 DELETE；同一 ID 再提交只返回原任务，避免删除随后重新上传的同名新版本。已明确失败后点击“重新删除”需要再次确认，并使用新 ID 删除当前版本。

文档列表不可用时，页面仍加载删除任务记录并展示恢复入口。同名任务优先展示需要恢复的记录，避免被后来阻塞的任务遮住。“恢复数据”用于未完成补偿；“检查并恢复任务”也可补写已提交但仍显示运行中的状态。恢复后仍需删除的，由管理员再次确认，不自动继续删除。网络故障和十分钟等待超时显示“状态待确认”，不当作删除失败。

## 接口

以下接口均需管理员身份，路径含 `/api` 前缀。

| 接口 | 作用 |
| --- | --- |
| `POST /api/documents/upload/async` | multipart 文件和可选 `upload_id`（32 位小写十六进制） |
| `GET /api/documents/upload/jobs` | 恢复页面任务列表 |
| `GET /api/documents/upload/jobs/{job_id}` | 查询状态，包含 `retryable`、`recovery_required`、`attempt` |
| `POST /api/documents/upload/jobs/{job_id}/retry` | 仅领取可重试的失败任务；重复领取返回 409 |
| `POST /api/documents/upload/recover` | 重试残留数据补偿；依赖仍不可用返回 503 |
| `POST /api/documents/upload` | 兼容同步上传，复用相同的持久任务和补偿流程 |
| `DELETE /api/documents/delete/async/{filename}?delete_id=...` | 创建可恢复的删除任务，可选稳定 ID 为 32 位小写十六进制 |
| `GET /api/documents/delete/jobs` | 读取持久化删除历史，与索引可用性无关 |
| `GET /api/documents/delete/jobs/{job_id}` | 核对删除进度与 recovery_required 状态 |
| `POST /api/documents/recover` | 统一恢复上传、删除事务；旧 upload/recover 路径继续可用 |
| `DELETE /api/documents/{filename}` | 兼容同步删除，复用同一补偿流程 |

暂存绝对路径不返回给浏览器。任务完成须以 `status=completed` 为准，HTTP 接收成功仅表示任务已收到。

## 持久化与部署边界

- 默认位置：`data/upload_jobs.sqlite3`、`data/document_transactions/`、`data/documents/.staging/`、`data/documents/`、`data/bm25_state.json`。前两项支持环境变量 `UPLOAD_JOB_DB_PATH`、`DOCUMENT_TRANSACTION_DIR`；BM25 支持 `BM25_STATE_PATH`。
- 成功任务确认持久化后清理对应日志、备份和暂存文件。失败任务的完整暂存文件保留，以支持重试；尚无自动过期策略，需关注磁盘占用。不要单独删除未恢复的日志或备份。
- 备份和迁移需协调保存上述目录与 PostgreSQL、Milvus 数据，不能把单独恢复任务库当作业务数据回滚。
- 运行 `uv run uvicorn backend.app:app --host 0.0.0.0 --port 8000 --workers 1`。同机同任务库的重复后端启动由进程锁拒绝；索引操作仍在唯一后端内串行执行。不要在服务运行中用独立脚本直接修改 BM25/索引。任务查询和管理界面保持可用，但长时间入库会推迟检索。
- 数据库宕机期间无法承诺旧版本仍可查询，依赖恢复后才能完成补偿。本实现覆盖应用异常和进程中断；整机断电、磁盘损坏需要额外的备份与存储可靠性措施。
- 上传和删除均有失败补偿、重启恢复及互斥保护。多实例、外部任务队列、版本化索引切换与自动清理不在本次实现范围。

## 单进程启动保护

后端启动先取得操作系统文件锁，再重新加载 BM25 并执行任务恢复。锁文件位置是任务库路径加 `.backend.lock`，默认 `data/upload_jobs.sqlite3.backend.lock`。同一任务库的第二个后端进程会在恢复及中断任务标记之前启动失败，提示使用 `--workers 1` 并关闭重复实例。

锁在整个服务生命周期内持有。正常退出后释放，进程被强制终止时由操作系统回收；文件仍留在磁盘是正常现象，不代表锁未释放。不要手工删除正在使用的锁文件。启动取消时会等待恢复线程结束，避免提前释放锁；关闭 lifespan 的请求会返回 503，无法绕过保护。取得锁后重新读盘，避免使用获得锁前加载的 BM25 旧状态；损坏或不支持的 BM25 状态会拒绝启动，需要检查文件或恢复备份。

关闭时先停止接纳新的索引操作，再等待实际工作线程完成当前事务及嵌套补偿，最后释放进程锁。即使请求被取消，也不会因其后台线程继续写入而与新进程重叠。关闭期间排队的操作拒绝执行；若存储调用持续阻塞，安全退出也会等待，强制结束整个进程后由下一次启动执行日志恢复。

首次升级此保护时，应停止旧版本后端再启动新版本，因为旧代码不会申请这把锁。开发热重载由旧进程退出、新进程取得锁完成交接。多 worker 管理器可能不断重试被拒绝的 worker，需将配置恢复为一个 worker。

这是同机共享任务库的单实例保护，不是多 worker 支持或跨主机分布式锁。不要让共享同一 Milvus/PostgreSQL 索引的实例配置不同任务库来绕过锁，也不要在服务运行期间执行绕过后端的索引写入脚本。

## 隔离验证

故障测试使用临时文件、SQLite 与存储替身，不删除或覆盖真实业务文档。覆盖解析/向量阶段失败、部分插入、发布文件失败、补偿失败、进程中断、已提交但状态未保存、幂等接收、显式重试和前端响应丢失。

```bash
python -m pytest test_process_guard.py test_document_transactions.py test_upload_job_persistence.py test_upload_recovery_api.py test_upload_recovery_boundaries.py test_upload_storage_consistency.py test_upload_recovery_frontend.py test_delete_recovery.py test_delete_recovery_frontend.py -q
```

Milvus SDK 回归使用当前安装的真实重试装饰器与模拟 RPC，父块回归使用真实 ORM 和模拟失效缓存；不是线上数据库宕机演练。
