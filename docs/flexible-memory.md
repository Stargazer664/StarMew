# 长期记忆使用说明

长期记忆现以 `memory_entries` 条目保存，支持任意短类别，而非仅姓名、公司等固定字段。正常聊天完成后，后台任务增量提取用户明确表达的信息；后台尚未完成时，下一轮可能暂时读不到刚说的内容。

## 可以怎样说

- “请记住：回答先给结论，再给解释。”——稳定的全局偏好。
- “以后只给结论，不再需要解释。”——更正已有偏好，不按文本长短判断。
- “SuperMew 项目只使用本地模型。”——明确项目范围；同一来源会话或提到该项目的新会话可以读取。
- “这次先处理登录。”——会话范围的临时安排。没有明确期限的计划不自动变成永久全局记忆。
- “忘记我的回答风格偏好。”——撤销对应条目，使其不再注入回答。

模型只能从新增用户消息提取；模型输出须带真实原文引用。项目名称必须出现在引用里；被错误标成全局的项目约束会保守限制在当前会话。若模型省略概述但有合法原文，直接保存原文；没有依据的输出失败并进入原有重试流程。语义判断仍依赖模型，原文校验不能保证其分类或理解永远正确。

## 保存、选择与兼容

条目保存内容、自由类别、稳定 key、范围、来源会话/消息 ID 和引用、记录时间、到期时间及状态。新版本使旧版本 `superseded`，撤销使条目 `revoked`；到期条目显示 `expired`。这些状态的条目不会进入回答上下文。按当前问题相关性选择并受 `CHAT_MEMORY_MAX_TOKENS` 预算限制。

PostgreSQL 保存主数据；旧 `facts` / `preferences` 按需导入为 `legacy` 来源，没有虚构消息出处。兼容响应仍提供有效全局条目的 `facts` / `preferences`。历史话题/摘要字段保留，但没有新增自动跨会话摘要写入。此机制不依赖 Milvus 记忆向量检索。

部署时正常重启单实例后端即可由 `init_db()` 创建新表，无需删除数据库或重建知识库。读取记忆不会等待后台模型提取。新表继承现有数据库备份方式。

## 管理接口（登录后使用）

| 接口 | 用途 |
|---|---|
| `GET /api/memory` | 返回本人记忆；新增 `entries` 字段含当前与历史版本、出处、范围、期限及状态 |
| `DELETE /api/memory/entries/{entry_id}` | 遗忘该身份的全部版本，阻止此前已保存但尚未提取的消息恢复它；其他用户返回 404 |
| `POST /api/memory/update?session_id=...` | 手动提取指定本人会话的增量；省略参数仍为 `default_session` |
| `DELETE /api/memory/reset` | 清除全部长期记忆并使旧排队任务失效；执行中的提取结束后再清除，之后新消息可重新建立记忆 |

前端尚未新增条目管理页面，可用 API 或自然语言更正/撤销。逐条遗忘保留审计版本；全部重置删除记忆表数据。两者均不删除聊天历史，当前会话仍可能从历史消息理解之前的信息。清除长期记忆后可新建会话验证效果。

## 验证范围

隔离 SQLite 测试覆盖事务、旧数据兼容、范围/用户过滤、过期、更正/撤销、队列恢复、执行中重置、HTTP 和同步/SSE 注入。真实本地 `qwen3.5:4b` 的五轮合成对话验证了偏好新增、更正、项目约束、撤销和排除假设人物信息。模型测试使用独立 SQLite，不改写业务数据；这不是大规模提取质量评测。此次未启动专用 PostgreSQL 环境，相关现有测试保持跳过。
